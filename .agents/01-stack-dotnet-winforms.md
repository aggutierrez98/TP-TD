# Stack .NET WinForms (v4.7.2)

1. **Framework**: El proyecto estrictamente usa .NET Framework 4.7.2. NO uses APIs, bibliotecas o sintaxis exclusivas de .NET Core, .NET 5+ u otras versiones modernas que no sean soportadas por C# 7.3.
2. **UI**: La interfaz de usuario es **WinForms**. No sugerir WPF, MAUI ni web. Todo el código de UI debe integrarse dentro de Formularios de Windows.
3. **Persistencia**: Preferir ADO.NET clásico, evitando Entity Framework Core a menos que se trate del Entity Framework 6 compatible con .NET Framework.
4. **Tema visual**: La UI usa **Krypton Toolkit** (version fija en `UI/UI.csproj`) con la paleta propia de `UI/Tema/FinanzappPaleta.cs` (modo claro, verde `#5DC47D`, texto `#3E3A4E`, fuente Segoe UI). Todo formulario hereda de `FormTraducibleBase` (`KryptonForm`) y usa controles Krypton (prefijos en `winforms-ui-control-naming`); los `KryptonButton` llevan `ButtonStyle = Custom1`. Solo quedan nativos `TreeView`, `CheckedListBox`, `NumericUpDown`, `RichTextBox` y `MenuStrip`, y `TemaFinanzapp` les aplica la paleta. No asignar `BackColor`/`ForeColor`/`Font` a controles Krypton (los ignoran): usar `StateCommon` o la paleta. Para migrar designers existe `.agents/scripts/migrar-designer-krypton.py`.
5. **Formularios redimensionables**: Todo formulario salvo `FormPrincipal` usa `FormBorderStyle.Sizable` y `MaximizeBox = true` (valores por defecto: no declararlos en el designer). El tamaño minimo es el de apertura y lo asigna `FormTraducibleBase` (no poner `MinimumSize` en el designer). Un hijo MDI nunca usa `WindowState = Maximized` (fusiona la barra de titulo con la ventana principal): el boton maximizar lo resuelve `FormTraducibleBase` y, para abrir ocupando el area de trabajo, se llama a `MaximizarEnAreaMdi()` en el `Load`. El contenido se acomoda con `Anchor`, sin escalar fuentes ni controles:
   - Grilla, arbol, lista, historial o mapa principal: `Top, Bottom, Left, Right`. Grupo de filtros o edicion arriba: `Top, Left, Right`; abajo de la grilla: `Bottom, Left, Right`.
   - Campo unico en su fila: `Top, Left, Right`. Botones: conservan tamaño; los de un grupo `Top, Left` (los alineados al borde derecho, `Top, Right`); Aceptar/Cancelar de dialogos, `Bottom, Right`.
   - Varios campos en una fila, o dos o mas zonas de datos que deben crecer en proporcion: `TableLayoutPanel` (prefijo `tlp`) con columnas `Percent` para lo que crece y `Absolute` para etiquetas y casillas; cada control conserva su posicion de diseño con `Margin`. Un `KryptonGroupBox` necesita su `EndInit()` en el designer: sin el, su `Panel` no acompaña al grupo cuando cambia de tamaño.
6. **Secretos de configuracion**: Toda clave de API, token o contraseña va en `UI/secrets.config` (ignorado por git), nunca en `App.config` ni en otro archivo versionado. `App.config` lo combina con `<appSettings file="secrets.config">` y el codigo lo lee igual que cualquier setting (`ConfigurationManager.AppSettings[...]`), porque .NET Framework solo lee el config del ejecutable, aunque quien lo consuma sea SERVICIOS. Al agregar un secreto, sumar su clave con valor vacio a `UI/secrets.config.example`. Si falta el archivo la app compila e inicia; el servicio que necesita el secreto lanza `ExcepcionTecnica` con una key traducible. Lo no sensible (modelo de Gemini, cadenas de conexion con `Integrated Security`) sigue en `App.config`.
